# 领域资料

高碑店的绿色建筑企业同时承接新建项目与老旧住宅改造。业主要求比较改造前后的
节能效果,但现场读数受采暖季与住户占用率影响,展会上的产品宣传数值也不等于
建筑实测值。本服务为现场检测团队提供测量档案:把建筑基线、设备更换、分时段
能耗与室内环境记录关联起来,并在第三方审核的窗口与口径下发布节能结论。

## 档案构成

- **建筑与基线**:建筑档案与改造前使用条件(占用率、采暖度日等),分开保存。
- **仪表与分时段读数**:现场实测能耗,只追加,不修改。
- **读数更正**:校准人员可更正(`adjust`)或剔除(`exclude`)错误仪表读数;
  原读数保留,更正形成完整审计链,生效值取最新一条。
- **设备更换与供应商宣传值**:宣传值(展会/样本数值)与实测读数分开保存,
  永不进入节能计算。
- **室内环境记录**:分时段的室内温度、湿度、占用率、采暖度日,用于解释
  读数受采暖季与占用率的影响,并供口径做归一化。
- **测量窗口**:第三方审核的时段(`open → validated/invalid`)。指标只能在
  `validated` 窗口上发布。
- **口径**:指标计算口径(纳入的仪表类型、是否按占用率/采暖度日归一化、
  最低覆盖率)。创建后不可修改,口径变化只能新增版本。
- **报告**:第三方发布的节能结论。发布时冻结完整溯源结果;任何角色不得
  改写,更正结论只能新建报告并注明 `supersedes_id`。

## 角色与边界

| 角色 | 能做什么 |
| --- | --- |
| `field_team` | 登记建筑、基线、仪表、读数、室内环境记录 |
| `calibrator` | 更正/剔除读数(必须填写原因) |
| `vendor` | 登记设备更换与宣传值;**不得改写第三方结论** |
| `inspector` | 审核窗口、定义口径、创建并发布报告 |
| `owner` | 只读查询 |

除 `/health` 外,所有接口要求 `X-Actor-Id` 与 `X-Actor-Role` 头,每次操作
都记录操作者。

## 节能计算

报告期能耗按口径归一化后与基线比较:

```
调整后报告期能耗 = 报告期能耗 × 占用率系数 × 采暖度日系数
占用率系数   = 基线占用率 / 报告期占用率     (口径启用时)
采暖度日系数 = 基线采暖度日 / 报告期采暖度日 (口径启用时)
节能量 = 基线能耗 − 调整后报告期能耗
```

- 只有完全落在窗口内、仪表类型被口径纳入、且未被剔除的读数参与求和。
- 覆盖率 = 纳入读数覆盖时长(并集)/ 窗口时长,低于口径的
  `min_coverage_ratio` 时拒绝发布。
- 口径要求归一化而窗口缺少占用率/采暖度日记录时,拒绝发布。

## 业主可见性

业主查询已发布报告时可以看到:

1. 计算使用了哪些时段(两个窗口的起止、每条纳入读数的时段);
2. 哪些读数被剔除、原值多少、谁因何剔除;
3. 哪些读数被更正、原值与更正值;
4. 口径变化造成的差额:`GET /buildings/{ref}/reports/{id}/caliber-comparison`
   用当前档案数据在每一版口径下重算同一对窗口,并给出相对报告口径的差额。

## 存储说明

`contracts/entities.json` 保存外部数据交换字段与角色约定;`fixtures/example.json`
是不含真实身份的交换示例。运行时持久化文件由 `DATABASE_PATH` 决定;时间字段
使用带时区偏移的 ISO 8601 字符串。

当前 Go 运行时使用纯标准库的内嵌快照存储(写临时文件后原子改名),与
`migrations/` 下的关系模式契约一一对应;存储层通过 `internal/store` 包与
HTTP 层解耦,需要 SQLite/PostgreSQL 部署时可在不改接口层的情况下替换后端。
