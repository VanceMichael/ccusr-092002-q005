# 领域资料

本服务面向高碑店绿色建筑企业的现场检测团队，覆盖**新建项目**与**老旧住宅改造**两类业务，回答业主一个问题：改造（或新建对比基线）到底省了多少能，这个数字是用哪些时段、哪些读数、什么口径算出来的。

## 为什么不能直接用现场读数做宣传

- **采暖季影响**：冬季供热能耗与非采暖季不在同一量级，比较的两个时段必须同为采暖季或按采暖度日（HDD）修正。
- **住户占用率影响**：入住率低、装修停用、分户空置都会压低能耗，看起来“节能”实际是没人用。占用率可按固定值或实际记录修正。
- **展会宣传值 ≠ 实测值**：供应商在展会/手册上的数值单独存放在 `marketing_claim*` 字段，标注来源，**不参与任何节能计算**；实测/铭牌值单独存放。

## 角色与不可改写边界

| 角色 | 标识 | 能做什么 |
|---|---|---|
| 现场检测团队 | `field` | 建筑、项目、设备、仪表、读数、室内环境、测量窗口、剔除、口径草稿、发布报告 |
| 校准人员 | `calibration` | 仅对错误读数**追加更正** |
| 第三方机构 | `third_party` | 对已发布报告**追加结论** |
| 业主 | `owner` | **只读**：查询报告全文（时段、读数、剔除、口径差额、第三方结论）与链校验 |
| 供应商 | — | **不是系统角色**，不持有令牌，不能登录、不能改数、不能改第三方结论 |

不可变规则：

1. 现场读数 `original_value` 一旦写入永不更新、永不删除。仪表错了由校准人员追加一条更正，报告同时显示原值与更正后值。
2. 第三方结论只追加；任何角色（含供应商）均不可改、不可删。
3. 报告发布后不可变；口径或数据变化发布**新版本报告**，并单列口径变化差额 `methodology_change_delta_kwh`。

## 测量窗口的读数集合冻结

窗口 `finalized` 时以当时的哈希链序号（`finalize_seq`）为锚冻结读数集合：此后补录的读数即使时段与窗口重叠，也**不进入**该窗口计算，而会在报告的 `recorded_after_finalize_readings` 中单列（连同录入时间与冻结锚点）。这样杜绝"终结后悄悄补读数改变结果"。读数在冻结前被校准更正不受影响——更正采用值始终反映到计算，且原值与原因可追溯。

窗口草稿期可按原因剔除读数（`excluded_readings`）；终结后不能再剔除。每块纳入仪表在每个窗口必须至少保留一条有效读数，否则窗口不能终结、指标不能发布。

## 发布闸门（指标只能在有效窗口和确定口径下发布）

发布节能指标必须同时满足：

- 基线窗口（baseline）与改造后窗口（post）均已 `finalized`；
- 两窗口绑定**同一个 `locked` 口径版本**（锁定后不可改，改动产生新版本）；
- 口径纳入的每块仪表在两个窗口内都有有效读数（被剔除读数不计，且剔除必须带原因）；
- 跨采暖季比较必须按口径做度日修正；占用率口径为 `actual` 时窗口内须有占用率记录。

任一条件不满足，发布请求返回 422 并列出阻断项，**不产生指标数字**。

## 业主在报告里能看到什么

每份报告固化一份 JSON 快照：

- 两个窗口的确切起止时段、采暖季标志、HDD；
- 纳入的每块仪表、每条参与计算的读数（原读数 + 更正值 + 更正原因）；
- 每条被剔除读数及其剔除原因；
- 使用的口径版本编号与全部参数；
- 原始合计、修正后合计、节能量、节能率；
- 若为后续版本：相较上一版报告的**口径变化差额**，明确哪些差异来自口径而非能耗本身。

## 数据载体与交换约定

`contracts/entities.json` 保存外部交换字段与枚举约定。`building_ref`、`meter_ref` 等来源编号仅表示提交方对同一记录的识别符，与系统主键（`BLD-n`、`MTR-n` …）分开；示例文件不包含真实个人资料。

规范关系模式见 `migrations/001_bootstrap.sql`（含不可变触发器）。运行时持久化为 `DATABASE_PATH` 指向的**仅追加哈希链事件日志**（每行含 `seq / prev_hash / SHA-256 载荷哈希`），事件类型与关系表一一对应；任何对历史行的篡改都会在链校验与报告锚点中暴露。时间字段统一使用带时区偏移的 ISO 8601 字符串。
